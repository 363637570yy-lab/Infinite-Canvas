# Infinite-Canvas 审计

## 边界

- **只读**。产出证据、覆盖矩阵和 findings，不实施修复、不改代码、不部署。
- 审计可扩大证据面，**不得扩大实现或授权范围**。
- "真实测试""全程监测""检查链路是否干净"属于验收和可观测性要求，不触发本 Skill。

## 审计域

| 域 | 关注点 |
|---|---|
| 生成链路 | 请求体构造 → 提交 → 轮询 → 落盘 → 画布回写的完整路径；失败、取消、超时、限流是否进入可追踪终态 |
| 协议合同 | 各协议字段映射是否与上游真实响应一致；未实现家族是否被静默降级；模型分类是否依赖 `supported_endpoint_types` |
| 画布数据 | 画布 / 会话 JSON 的读写是否统一走既有路径；有无裸文件操作或路径拼接；刷新恢复是否完整 |
| 素材与产物 | `assets/`、`output/`、`runtime/` 的写入、清理与引用一致性；有无孤儿文件或悬空引用 |
| 配置与凭据 | API Key、代理、中转站配置是否只存在于 `API/.env` 与 `runtime/data/api_providers.json`；有无硬编码或入库 |
| 规则符合性 | 实现是否违反 `AGENTS.md` 中的架构、协议、部署条款 |

## Finding 分级

| 级别 | 处置 |
|---|---|
| `target_failure` | 本轮目标缺陷，必须报告并由主代理修复 |
| `direct_regression` | 当前改动造成的回归，必须报告并修复 |
| `validation_defect` | 验证本身有问题，只修验证 |
| `adjacent` / `historical` | 相邻或历史问题，**只报告不修**；相邻 P0 暂停上报，未经授权不得自动修复 |

## 方法

1. 冻结审计范围：明确要审哪些域、哪些文件、哪个提交。
2. 只读取证：代码、真实接口响应、测试、运行日志。不得为了取证触发付费生成或写操作。
3. 建立覆盖矩阵：逐项标注已覆盖 / 未覆盖 / 无法覆盖及原因。
4. 每条 finding 必须给出：文件与行、可复现的失败场景、影响范围、建议级别。无法复现的只能标为"疑似"。
5. 报告未覆盖项和取证限制，不得把未验证的推断写成结论。

## 交付

输出覆盖矩阵 + 按级别排序的 findings + 未覆盖项与残余风险。不实施任何修复。
